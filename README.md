## 1단계 설계

- `academy/inputs.py`: 문제 PDF·정답 PDF·OMR XLSX의 세 역할을 구분합니다. 누락·빈 파일·확장자 위장·기본 형식·크기 제한을 검사합니다. 파일을 디스크에 저장하거나 코드를 실행하지 않습니다.
- 파일 이름 대신 역할과 파일 내용의 해시로 식별값을 만듭니다. 다음 단계에서는 이 값이 바뀌면 이전 분석·대화를 초기화합니다.
- PDF 헤더 검사와 XLSX 컨테이너 검사는 내용 파싱의 성공을 의미하지 않습니다. 암호화 PDF·OMR 열/학생 식별자·정답/배점·문항 일치 검증은 2단계에서 수행합니다.
- 기본 제한은 파일당20MiB, 엑셀 내부80MiB/2,000개 항목이며 `InputLimits`로 조정합니다. 고객의 학생 수를10명 또는120명으로 고정하지 않습니다.
- `academy/config.py`: mini/nano를 자동 사용하지 않는 모델 후보를 명시합니다. 기본 `gpt-6.1-sol`, 복잡한 작업 `gpt-6-astra`는 접근 권한·호환성·정확도·시간 검증 전 후보입니다. 내부18초 설정은 시간 정책이며 이 단계가 20초 달성을 입증하지는 않습니다.
- 학생 자료·정답·배점·API 키는 코드와 테스트에 포함하지 않습니다. 실제 업로드 파일명과 본문은 기본 객체 표시나 오류 메시지에 출력하지 않습니다.

## 2단계 파싱

- `academy/parsing.py`의 `parse_exam(validated_inputs)`가 정답·응답·문제·공유 지문·페이지 출처를 반환합니다. 정답이나 배점을 코드에 내장하지 않습니다.
- 정답 PDF는 격자 표의 `문항번호/정답/배점` 반복 열을 지원합니다. 정답의 중복·누락·비정상 배점과 문제지 문항 불일치를 차단합니다. 스캔 PDF의 OCR이나 다른 표 형식은 자동 추정하지 않습니다.
- 제공 문제지는 두 단이므로 기본 `question_columns=2`입니다. 한 단 자료는 `1`로 지정합니다. 공유 지문은 관련 문항들을 포함한 원문 구간 전체로 연결하며 선택지와 그림의 완전한 구조화를 의미하지 않습니다.
- OMR은 `OMR_응답` 시트의 `학생명`, `Q01` 형식 열을 사용합니다. 열 순서가 바뀌어도 문항 번호로 연결합니다. 학생명 중복·빈 식별자·수식·오류·1~5 밖의 값을 차단합니다. 파서는 미응답을 `None`으로 보존하고, 별도 채점 모듈이 점수를 계산합니다.
- PDF당100페이지, 문제 텍스트200만 자, OMR 학생1만 명/1,001열을 상한으로 둡니다. 시간·메모리의 강제 격리를 보장하는 제한은 아닙니다.
- 듣기 음원·그림·표·밑줄은 텍스트만으로 재현할 수 없습니다. 원본 업로드와 페이지 출처를 유지하고, 이후 생성 단계에서 원문 확인 또는 제한 안내가 필요합니다. 프롬프트 인젝션 방어는 아직 구현하지 않았습니다.

## 3단계 채점·결과 재사용

- `academy/grading.py`: 정답·배점은 파싱 결과만 사용합니다. 미응답은 오답(0점), 감점 없음. 업로드된 전체 학생의 모집단 표준편차(`ddof=0`)를 사용합니다. 계산 중 반올림하지 않으며 엑셀 표시만 소수 둘째 자리까지 합니다.
- 오답자가 있는 문항을 오답자 수 내림차순·문항 번호 오름차순으로 정렬해 최대3개를 선정합니다. 동률 경계 문항은 별도로 보존합니다. 전원 정답이면 오답 상위 문항은 없습니다. 동점 학생의 순위는 `1,1,3` 방식이며 최저 점수 학생 조회는 동점자 전원을 반환합니다.
- `academy/export.py`: 성적 개요·학생 성적·문항별 정답 여부·문항 통계·원문 확인의 다섯 시트를 바이트로 생성합니다. 학생 이름은 수식으로 실행되지 않는 문자열로 저장합니다. 수식은 사용하지 않고 동일한 Python 계산 결과를 기록합니다. 서버 파일 저장은 하지 않습니다.
- `academy/analysis.py`: 파싱·채점·엑셀 결과를 한 묶음으로 반환합니다. 파일 식별값·파이프라인 버전·단 수로 분석 키를 만듭니다. UI는 현재 세션에서 같은 분석 결과를 재사용합니다. 파서·계산 정책이 바뀌면 파이프라인 버전도 갱신해야 합니다.
- 문항별로 듣기·그림/도표·표·밑줄 의존 경고를 휴리스틱으로 추가합니다. 원문 배치는 모든 문항에서 확인 대상으로 남깁니다. 이 표시는 완전한 탐지나 생성 가능 판정이 아니며, 원문 영역 좌표·이미지 분석은 아직 없습니다. 생성 단계에서 부족한 내용을 추정하지 않아야 합니다.

```python
from academy.analysis import analyze

analysis = analyze(validated_inputs)  # validate_uploads()가 반환한 객체
grades = analysis.grades
excel_bytes = analysis.excel
# 이후 UI의 세션에 analysis를 보관하고 화면·다운로드·챗봇에서 함께 사용합니다.
```

## 4단계 화면과 세션

- `streamlit_app.py`가 두 페이지를 등록하고 사이드바 업로드·분석 시작·자료 지우기를 처리합니다. 업로더는 공통 진입점에 있어 페이지 이동 시 자료를 유지합니다.
- 소개 페이지에는 분석 페이지로 이동하는 링크를 표시하며, 분석 시작 버튼은 분석 페이지에서만 제공합니다. 분석 직후 강제 페이지 전환을 하지 않아 업로더 상태 초기화로 결과가 지워지는 경로를 제거했습니다.
- `app_pages/home.py`: 소개와 자료 형식 안내. `app_pages/results.py`: 성적 지표·학생 성적·문항 통계·원문 확인·엑셀 다운로드입니다.
- 세 파일이 준비되어야 분석 버튼을 사용할 수 있고, 분석 성공 후에만 엑셀 다운로드가 활성화됩니다. 오류 시 이전 결과를 표시하지 않습니다.
- `academy/session.py`: 파일 내용·역할·단 수·파이프라인 버전이 바뀌면 이전 결과와 향후 대화 상태를 삭제합니다. 파일명만 바뀌고 내용이 같으면 결과를 재사용합니다. 다른 사용자와 공유하는 전역 캐시는 사용하지 않습니다. 새로 고침/세션 종료 후 상태 보존을 보장하지 않습니다.
- 분석 완료 후 챗봇 연결 설정에 API 키를 입력하면 대화가 활성화됩니다. 키가 없으면 채팅만 비활성화됩니다.
- 업로드는 세션 메모리에서 처리하고 분석 결과를 서버 파일에 저장하지 않습니다. 엑셀은 내려받는 사용자의 기기에 저장됩니다. 인증·사용자 권한·공개 배포 운영 검증은 아직 하지 않았습니다.

AppTest에서는 실제 업로더 위젯을 렌더링하되 반환값에 합성 파일을 주입합니다. 소개 페이지에서 분석을 시작할 수 없고 분석 후 강제 페이지 전환이 호출되지 않는 회귀 검증을 포함합니다. 이 방식으로는 브라우저의 실제 업로드 상태 초기화를 직접 재현할 수 없어 초기 테스트가 문제를 놓쳤습니다. 실제 학생 자료나 과제 정답은 테스트·저장소에 포함하지 않습니다.

4단계 이후 사용자가 실제 브라우저 결과 화면과 다운로드 파일을 제공했습니다. AI가 화면 수치와 다운로드된 다섯 시트 전체 값을 원본 재분석 및 독립 계산과 대조했고 일치를 확인했습니다. Excel 프로그램의 실제 화면 렌더링은 검증하지 않았습니다.

## 5단계 챗봇

1. 패키지 추가 후 앱을 재시작합니다: `python -m pip install -r requirements.txt`, `python -m streamlit run streamlit_app.py`.
2. 자료를 업로드하고 분석합니다. 성적 대화의 **챗봇 연결 설정**에 OpenAI API 키를 입력합니다. 키를 채팅·소스·GitHub에 붙여넣지 마세요. 환경변수 `OPENAI_API_KEY`도 지원합니다. 이 앱은 .env 파일을 자동으로 읽지 않습니다.
3. 질문하면 `academy/chat.py`의 LangGraph `prepare → route → dispatch → 업무 노드 → advance → finish`가 구조화 계획을 검증하고 성적 조회 또는 생성/검수를 수행합니다. 평균·중앙값·표준편차·최저 점수 동점자·학생 점수는 기존 계산 결과를 조회해 문장으로 출력합니다. 복합 요청은 최대6개 작업, 문제 생성은 한 번에1개입니다.
   학생 번호는 업로드 목록에서 읽으며 `번호학생`·`번호번 학생`·`번호 학생`을 같은 식별자로 정규화한 후 가명화합니다. 목록에 없는 번호와 중복 번호는 기존 신원으로 대신 연결하지 않습니다. 최근 대화의 사용자 자기소개를 후속 질문에 활용하지만, 이것은 로그인이나 실제 본인 인증이 아닙니다.
   목표 순위 질문은 `rank_goal`로 분류해 Python으로 계산합니다. 다른 학생 점수 고정·공동 순위 허용을 전제로 필요한 점수와 고배점 오답부터 정정한 최소 문항 수를 계산합니다. 전체 문항 대비 정답률 증가를 %포인트로 표시하며, 상대 증가율과 구분합니다. 단독 순위를 보장하거나 다음 시험 성적을 예측하는 기능은 아닙니다. 분석 버전을v4로 올려 이전 세션 결과/대화를 무효화했습니다.
4. 최근 대화12개 메시지(메시지당4,000자)를 모델에 전달하고 자기소개 학생 가명은 세션에 별도 보관합니다. UI 기록은 최근24개 메시지만 보관하며 데이터 변경 시 삭제됩니다. 전체 과거 대화를 무제한 기억하지는 않습니다.
5. 학생 식별자는 세션 내 가명으로 바꾸고 이메일·국내 휴대전화 패턴을 가립니다. PrivacyMiddleware가 모든 분류·생성·검수 payload에 공통 전처리를 적용합니다. 완전한 개인정보 탐지는 아닙니다. 원문 이미지의 픽셀 마스킹은 하지 않습니다.
6. 생성 기준은 요청 문항 또는 실제 오답1위입니다. 원문 지문/페이지를 제공하고 선택지5개·중복 선택지·정답 범위를 코드로 검사한 뒤 모델이 독립 검토합니다. 검수 실패 시 충분한 시간 여유가 있으면 피드백을 반영해 최대 한 번 수정·재검수하며 최종 승인된 문제만 공개합니다. 원문 부족·API 연결 오류는 반복하지 않습니다. 도표·표·밑줄 의존 문항은 원문 페이지 이미지를 생성/검수에 함께 전달합니다(최대2페이지). 음원·대본이 없는 듣기는 생성하지 않습니다. 예측 질문/과제 정답을 하드코딩하지 않습니다.
7. 분류는 `gpt-6.1-sol`, 생성/검수는 분류 모델의 complex 판단에 따라 `gpt-6.1-sol` 또는 `gpt-6-astra`를 사용합니다. mini/nano로 자동 대체하지 않습니다. 계정에서 해당 모델을 이용할 수 있는지는 실제 호출 확인이 필요합니다.
8. 전체 그래프 비동기 실행에18초 한도, 요청 내 SDK 클라이언트 공유·자동 재시도0회, 오류 세부정보 비공개를 적용합니다. 이미지 변환은 취소 가능한 별도 프로세스와 세션 캐시를 사용합니다. 취소/이미지 처리/렌더링 오버헤드까지 포함해20초를 보장하는 측정 결과는 아직 없습니다. 실패 안내는 정답 성공으로 간주하지 않습니다.
9. 내부 정보 공개 요청 일부를 로컬 패턴으로 차단하고 구조화 분류에도 거절 지침을 줍니다. 출결 등 미제공 정보는 답변을 보류합니다. 우회 공격 전체에 대한 방어를 보장하지 않습니다. 임의 코드 실행·외부 검색 도구는 없습니다. LangSmith 자동 추적은 호출 범위에서 끄고 OpenAI 응답 저장은 `store=False`로 요청합니다.

공식 참고: [OpenAI 구조화 응답](https://developers.openai.com/api/docs/guides/structured-outputs), [Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [Astra](https://developers.openai.com/api/docs/models/gpt-6-astra), [LangGraph 그래프](https://docs.langchain.com/oss/python/langgraph/quickstart). 개발 문서 확인에만 사용했으며 앱은 외부 웹 검색을 하지 않습니다.
